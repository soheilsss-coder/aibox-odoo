# راهنمای نصب دستگاه AIBox (مینی‌PC / Raspberry Pi)

> هدف: یک دستگاه تحویل‌دادنی که با روشن‌شدن، خودش بالا بیاید؛ شما از پنل فروشنده
> آن را برای شرکت هدف شخصی‌سازی کنید، تحویل بدهید و بروید.

---

## ۱. سخت‌افزار پیشنهادی
- مینی‌PC (مثلاً Intel N100) یا Raspberry Pi 5 (۸ گیگ به بالا)
- SSD/MicroSD ۶۴ گیگ به بالا
- اتصال شبکه به همان شبکه‌ای که کاربران مشتری هستند

## ۲. نصب (یک بار، ۲۰ دقیقه)
۱. Ubuntu 22.04+ یا Debian 12 را روی دستگاه نصب کنید و به شبکه وصل کنید.
۲. کد را بگیرید و نصاب را اجرا کنید:

```bash
sudo apt update && sudo apt install -y git curl
git clone https://github.com/soheilsss-coder/aibox-odoo.git /opt/aibox
cd /opt/aibox
sudo bash sandbox/appliance_install.sh            # بدون دادهٔ دمو
# یا با دادهٔ دمو برای نمایش به مشتری:
sudo bash sandbox/appliance_install.sh --demo
```

۳. در پایان نصاب، **رمز هر دو ادمین** را چاپ می‌کند — همان لحظه یادداشت کنید.

نتیجه:
- مسیرها: کد در `/opt/aibox`، داده در `/var/lib/aibox`
- سرویس `aibox-appliance` با بوتِ دستگاه خودکار بالا می‌آید و اگر کرش کند ری‌استارت می‌شود

### دو ادمین، یک صفحهٔ ورود

| نقش | ورود | کجا می‌رود |
|---|---|---|
| **ادمین سیستم** | `admin` + رمز چاپ‌شده | کنسول سیستم (`/aibox-odoo/admin.html`) — شخصی‌سازی، ماژول‌ها، کاربران، تحویل |
| **ادمین توسعه‌دهنده** (شما) | `developer` + رمز چاپ‌شده | **کنسول توسعه (`/aibox-odoo/devconsole.html`)** — همهٔ امکانات سیستم + مرورگر مدل‌ها/دیتا، خودکارسازی (کرون‌ها)، لاگ زندهٔ سرور، مدیریت نقش توسعه‌دهنده |

هر دو از **همان صفحهٔ ورود** وارد می‌شوند؛ سیستم بر اساس نقشِ حساب، خودش مسیر درست را باز می‌کند.
حسابِ توسعه‌دهنده فقط باید توسط خودتان ساخته/واگذار شود و در بخش «Users & Roles» کنسول توسعه قابل مدیریت است.

### نصب کاتالوگ کامل (اختیاری — مشتری «همه‌چیز» خریده)

اگر می‌خواهید همهٔ ماژول‌های اودو از ابتدا نصب باشند:

```bash
AIBOX_WS=/var/lib/aibox python3 /opt/aibox/sandbox/mass_install_modules.py
```

همهٔ ماژول‌های قابل‌نصب را دسته‌دسته نصب می‌کند، ماژول‌های مشکل‌دار را خودکار ایزوله و
گزارش می‌دهد (معمولاً فقط یک پیش‌نیاز پایتونی لازم است).

## ۳. هوش مصنوعی کاملاً لوکال روی خود دستگاه (Ollama)
روی همان دستگاه:

```bash
curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.2        # یا هر مدل دیگر
sudo systemctl enable --now ollama
```

سپس در پنل فروشنده → **AI Engine** → پرست «Ollama on this device»:
- Base URL: `http://127.0.0.1:11434/v1`
- Chat model: `llama3.2` (هر چیزی که pull کردید)
- کلید لازم نیست (خالی بگذارید)

دکمهٔ **Test connection** باید جواب واقعی مدل را نشان دهد؛ بعد **Save & apply**.
از این لحظه چت پلتفرمِ مشتری کاملاً روی دستگاه خودش اجرا می‌شود — بدون اینترنت، بدون کلید، بدون هزینه.

> گزینهٔ دوم: هر سرویسسازگار با OpenAI (vLLM، LM Studio، …) — همان فرم، همان تست.

## ۴. شخصی‌سازی برای شرکت هدف (از پنل فروشنده)
1. **Branding** — نام/شعار/رنگ‌ها/لوگو/فاوآیکون + پیام خوش‌آمد صفحهٔ لاگین مشتری
2. **Modules** — بسته‌های آماده (Sales/Accounting/…) یا نصب/حذف تکی
3. **Users** — ساخت کاربر(های) اول مشتری با رمز
4. **Token Usage** — اگر می‌خواهید، سقف مصرف ماهانه بگذارید
5. **Handover** — چک‌لیست همه‌سبز → تغییر رمز ادمین → **Clean test data** → پشتیبان‌ها → **Generate certificate**

## ۵. به‌روزرسانی دستگاه (بعداً، برای خدمات)
```bash
sudo bash /opt/aibox/sandbox/appliance_update.sh
```
کد جدید را می‌کشد، ماژول‌ها را آپگرید می‌کند و سرویس را ری‌استارت می‌کند.

## ۶. نکته‌های مهم
- کلید سرویس‌دهندهٔ ابری (در صورت استفاده) فقط داخل دستگاه ذخیره می‌شود و در پشتیبانِ Config عمداً نیست — بعد از ری‌استور، دوباره در پنل واردش کنید.
- پنل فروشنده فقط با رمز ادمین باز می‌شود؛ کاربران مشتری هیچ راهی به آن ندارند.
- پورت‌ها: وب `18069` (همه‌چیز از همان)، مغز Nova `8001`، امبدینگ `8002`، ردیس `16379` — همه فقط روی خود دستگاه.
- اگر دستگاه پشت مودم مشتری است، مشتری با `http://IP-داخلی:18069` استفاده می‌کند؛ برای دسترسی خودِ شما از بیرون، تونل/پورت‌فورواردینگ را **موقت** باز کنید و بعد از تحویل ببندید.
